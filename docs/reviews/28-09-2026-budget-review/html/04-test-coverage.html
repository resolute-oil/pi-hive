4.2 · Where the gaps are

G1

Second checkDispatchBudgets after queue

High

The dispatcher calls checkDispatchBudgets twice: once before slot acquisition (src/engine/dispatch.ts:252) and once after (src/engine/dispatch.ts:302). The first is well-tested; the second is not. The function itself is tested in tests/governance.test.ts, but the call-from-dispatch pattern isn't.

G2

getSessionStats() overwrite order

Critical

The third-mystery bug hypothesis is that the order of (stats overwrite → delta computation → governanceTokens accumulation) is wrong, or that getSessionStats() returns unexpected values for aborted sessions. No test exercises this.

Tests use deterministic fake createSession factories that always return predictable getSessionStats values. A real SDK abort path is not exercised.

G3

Abort-then-getSessionStats() race (Bug 3)

Critical

Even if the order is correct, an aborted session might cause getSessionStats() to return values that disagree with the live accumulation. Tests do not exercise this race.

What such a test would look like:

1. Set up a fake session whose prompt() calls runController.abort() mid-stream.
2. Have getSessionStats() return a different value than the live accumulation.
3. Assert the post-run governanceTokens matches expectations.

Such a test would have caught Bug 3 if it had existed before the user's deployment test.

G4

Concurrent parallel delegations

Medium

The orchestrator can call delegate_agent twice in the same turn (parallel tool calls). The budget counter is updated by sibling handlers in any order. Tests do not exercise parallel updates to the team total.

G5

Operator commands without UI

Medium

endWorkerSession, compactWorkerSession, respawnWorkerSession are tested. The dashboard UI that invokes them is missing. The gap is in the dashboard, not the engine.

4.3 · Test architecture observations

The tests are well-structured. Three layers of test fidelity, from fast pure-function tests to higher-fidelity dispatchAgent tests with fake sessions.

Layer 1 — Pure-function tests

tests/governance.test.ts and tests/budget-strategy.test.ts use runtime(name, overrides) and state(runtimes, settings) helpers to construct mock state. Fast, deterministic. Catches the budget math, the strategy resolution, and the operator command semantics.

Layer 2 — Dispatch with fake sessions

tests/dispatch-usage.test.ts uses createAgentSession injection to drive dispatchAgent end-to-end with fake sessions. Higher fidelity; catches the ordering and counter-reset bugs (Bug 1, W1.1, R3-1.1).

Layer 3 — Real SDK tests

Not present. No test exercises a real Pi SDK session.prompt() + runController.abort() + getSessionStats() race. The third-mystery bug lives in this layer.

The fake-session pattern can be extended. A test that drives prompt() to call runController.abort() mid-stream and has getSessionStats() return a different value than the live accumulation would have caught Bug 3. The architecture supports it; the test just needs to be written.
