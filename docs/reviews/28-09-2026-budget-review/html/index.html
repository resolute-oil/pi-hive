Key findings

  1. Three counters, three write sites, three read sites. The dual/triple counter system encodes a state machine in source code via ?? fallthroughs. Every bug in the timeline is a consequence of this design.
  2. Three fresh=true bugs in five commits. Bug 1 (ordering), Bug 2 (mid-run check) fixed. Bug 3 (post-abort end-of-run math) unresolved per ../raw-evidence/2025-09-28-fresh-true-budget-bug-unresolved.md.
  3. Test coverage is strong on deterministic paths, weak on races. The fake-session pattern catches what it covers; it doesn't cover runController.abort() racing getSessionStats().
  4. Pi-docs alignment has four gaps. State in closure not in CustomEntry; no ctx.signal propagation; no UsageEntry for worker spend; pre-dispatch check not tool_call blocking.
  5. Operator intervention is wired before the UI exists. Three dispatch commands are correct and tested; the dashboard's intervention buttons are missing.
  6. Two latent SDK issues surfaced in the online SDK refresh. Issue 8: final-message accumulation uses agent_end instead of agent_settled. Issue 9: session.dispose() is never called on the old runtime during respawn (listener leak). Both are low-severity follow-ups; neither blocks the bug-class fix.
