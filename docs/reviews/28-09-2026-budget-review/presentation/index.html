Refactor plan · 2026-09-28

Budget system, redesigned around Pi

Replace the dual-counter budget layer with a single-source-of-truth design built on Pi SDK primitives. Collapse three counters to one ledger. Make the fresh=true bug class structurally impossible. Expose six EOL/respawn commands instead of three.

Baseline: feat/budget-strategy @ 9f950fb Scope: ~2,100 LOC rewritten · ~50 new tests · 13 features Status: Awaiting user decisions on 13 open questions

Page 2 · Why

The problem

Nine structural issues and three fresh=true bugs in the current implementation.

Nine structural issues

From the prior session's current-state analysis:

1

Dual/triple counter system

Critical

Three independent counters (runtime.*, governanceTokens, effectiveTokens) with ?? fallthroughs encoding a state machine in source code. Every refactor that touches counters reintroduces the bug class.

2

Overwrite/accumulation race

High

The mid-run live updates are overwritten by getSessionStats() at agent_end; delta math runs on post-overwrite values. If the SDK's stats return different values than live accumulation (aborted session, missed message_end), the delta is wrong.

3

fresh=true is overloaded

High

fresh=true couples four operations (reload config, archive session, zero counters, start new session). The coupling is what made Bug 1 possible.

4

Dashboard intervention UI missing

Medium

Three dispatch commands are correct and tested, but the dashboard UI to invoke them is missing.

5

Strategy layered without isolation

Medium

budget-strategy.ts mixes four concerns: event emission, strategy resolution, prompt mutation, and dedup.

6

Test coverage weak on races

Medium

Deterministic paths are well-pinned. The abort-then-getSessionStats race is not.

7

fresh=true lives in dispatch.ts

Low

freshResetRuntime belongs in the budget module, not the dispatcher.

8

agent_end instead of agent_settled

Low

Pi's canonical "Pi will not continue automatically" event is agent_settled, not agent_end.

9

session.dispose() never called on respawn

Low

Old session's session.subscribe() listener leaks because dispose() is absent.

Three fresh=true bugs

BugSymptomFixStatus
Bug 1 fresh=true doesn't reset; respawn blocked Move freshResetRuntime before checkDispatchBudgets Fixed commit 3be33f6
Bug 2 Mid-run check sees stale governanceTokens=0; worker overruns by 26x workerConsumedTokens returns live values mid-run Fixed commit 3be33f6
Bug 3 Post-abort end-of-run math: tokens=0 but remaining.tokens=0 Structural — collapsed to getSessionStats() as source of truth Open closed by this refactor
Key insight

The bug class lives in the dual-counter system. Every fix so far has been a defensive guard in the read sites. A structural fix collapses the counters to one source of truth.

Page 5 · Architecture

What replaces it

New module structure, single source of truth, persistent ledger.

Module structure

src/engine/budget/
├── ledger.ts          # BudgetLedger — class wrapping CustomEntry persistence
├── policy.ts          # BudgetPolicy — pure decision functions (no I/O, no SDK)
├── strategy.ts        # WorkerBudgetStrategy — enum + resolver
├── events.ts          # installBudgetEventHooks(session, ledger, caps, controller)
└── worker-tools.ts    # delegateAgent + 6 operator commands
└── index.ts           # Barrel re-exports

The single source of truth

Per pi-sdk-session-api.md#1.3, session.getSessionStats() returns:

{
  sessionFile, sessionId,
  userMessages, assistantMessages, toolCalls, toolResults, totalMessages,
  tokens: { input, output, cacheRead, cacheWrite, total },
  cost: number,
  contextUsage: ContextUsage
}

tokens.total = input + output + cacheRead + cacheWrite — cumulative across the session's lifetime, including aborted messages whose Usage field was populated.

Why this kills the bug class

The old design had three write sites (message_end, agent_end, compaction_end) updating three different counters. The new design has zero write sites for cumulative spend — the SDK maintains getSessionStats() internally. We just read it.

The persistent ledger

Per Pi docs §4 and §9, CustomEntry is the right tier for "durable data excluded from model context." Branch-aware via getBranch(); survives /reload, /tree, /fork.

type BudgetLedgerEntry = {
  type: "custom";
  customType: "pi-hive-budget-ledger";
  data: {
    caps: { workerTokens?, workerCostUsd?, workerRuns?, workerDepth?,
            teamTokens?, teamCostUsd?, teamRuns? };
    cumulative: { tokens: number; costUsd: number; runs: number };
    writtenAt: number;
    agentSlug: string;
    marker?: "warning" | "exhausted" | "checkpoint";
  };
};

compaction_endAlways—

Key insight

fresh=true no longer means "do four operations in this order." It means "create a new session." The session naturally has no entries, so getBranch() returns nothing, the ledger is empty, the cap is the cap. Bug class is structurally impossible.

Page 10 · Trade-offs

Pros, cons, and pitfalls

What this refactor gives us, what it costs, and what to watch out for.

✓ Pros

  • Single source of truth. getSessionStats() IS the cumulative source. No more dual-counter state machine.
  • Bug 3 becomes structurally impossible. The dual/triple counter math disappears.
  • Branch-aware + reload-safe. getBranch() re-derives from CustomEntrys; survives /reload, /tree, /fork.
  • Six EOL commands. End / compact / respawn / pause / snapshot / restore — far more flexibility than the current 3.
  • Pi-native. Every primitive from Pi's documented API; no parallel infrastructure.
  • Throw-to-refuse. Per Pi docs §2; clean error semantics for the orchestrator.
  • Worker sees warnings. Via appendCustomMessageEntry("budget_warning", ..., display=true); the agent can act on the hint.
  • Mode-independent. Works in TUI, RPC, print, JSON modes.
  • Race-testable. ~6 new race tests covering the previously untested paths.
  • Typebox-validated config. Invalid combinations surface at config-load with structured errors.

✗ Cons

  • ~2,100 LOC rewritten. Substantial change surface; risk of regression in adjacent code.
  • Existing tests break during migration. All 510 existing tests must be rewritten to use the new primitives (in-place rewrite, not deletion).
  • Config schema change. User configs need migration; one release of dual-format support.
  • Telemetry event name choices. Keep old names for dashboard compat, or break the dashboard — both have costs.
  • PR #54 conflict. The open budget-strategy PR conflicts with the refactor; one must close.
  • Sensible defaults are a behavior change. Projects with no caps will now have defaults; users may hit friction.
  • agent_settled semantics may differ from agent_end. Latent edge cases around recovery cycles; race tests will surface divergence.
  • Dashboard UI still separate. F13 is a separate PR; the engine changes ship without UI surface initially.

⚠ Pitfalls

  • Stale process. After editing src/engine/budget/** or src/engine/dispatch.ts, restart: PID=$(lsof -nP -iTCP:43191 -sTCP:LISTEN -t) && kill "$PID" && just pi-dev
  • Worktree force-remove. Never run git worktree remove --force without git status precheck (HANDOFF pitfall #29).
  • No upstream pushes. Only origin (resolute-oil fork); never upstream (demetere source).
  • No git push origin main. Changes reach main via PRs the user merges.
  • Math.random() / Date.now() / setTimeout in race tests. All three make tests non-deterministic; grep audit required.
  • Bun-only code. Isolate to dashboard/server paths; core extension must load even when Bun is unavailable.
  • Closure-captured state. The old design's bug class lives in closure-shaped mutable maps; the new design must NOT regress to this.
  • Disk-level reload preservation. getBranch() re-derivation is the structural fix — do NOT rely on in-memory state across reload.
  • Promote compact strategy only on user approval. C5 is conditional; landing it without user buy-in is scope creep.
  • Skip auto-merge. Per AGENTS.md, never auto-merge via branch protection or settings.
